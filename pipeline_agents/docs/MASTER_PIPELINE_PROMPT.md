# Мастер-Промпт для Запуска Многоагентного Пайплайна Разработки

---

## ВАЖНО: Перед запуском заполните все поля, помеченные `[...]`

---

## Часть 1. Описание разрабатываемой системы

### 1.1. Человеческий замысел (Human Intenфtф)

```
[ОПИШИТЕ ЗДЕСЬ ЧТО ВЫ ХОТИТЕ РАЗРАБОТАТЬ]

Примеры:
- "Создать Android приложение для заметок с поддержкой синхронизации"
- "Разработать веб-сервис для управления задачами с календарём"
- "Создать бэкенд API для интернет-магазина"

Включите:
- Основную цель продукта
- Ключевые функции (если есть)
- Целевую платформу (если важно)
```

### 1.2. Дополнительный контекст (опционально)

```
[ДОПОЛНИТЕЛЬНАЯ ИНФОРМАЦИЯ]

Примеры:
- Особые требования к производительности
- Предпочтительные технологии
- Ограничения по времени/ресурсам
- Ссылки на похожие проекты
```

## Часть 2. Конфигурация пайплайна

### 2.1. Рабочая директория проекта

```
[УКАЖИТЕ ПУТЬ К ПРОЕКТУ]

Пример: /home/user/projects/my-app
```

### 2.2. Текущее состояние проекта

```
[ВЫБЕРИТЕ ОДИН ВАРИАНТ]

- [ ] Существующий проект (есть код для анализа)
```

## Часть 3. Параметры выполнения

### 3.1. Уровень автоматизации

```
[ВЫБЕРИТЕ РЕЖИМ]

- [ ] Полуавтоматический - на каждом этапе запрашивать подтверждение

```

## Часть 4. Запуск Оркестратора

Скопируйте и выполните следующий промпт после заполнения всех полей выше:

---

```markdown
# ЗАПУСК ПАЙПЛАЙН-ОРКЕСТРАТОРА

Я запускаю многоагентный пайплайн разработки.

## КОНТЕКСТ ЗАПУСКА

### Человеческий замысел (Human Intent):
[ВСТАВЬТЕ ВАШЕ ОПИСАНИЕ ИЗ ЧАСТИ 1.1]

### Дополнительный контекст:
[ВСТАВЬТЕ ВАШ КОНТЕКСТ ИЗ ЧАСТИ 1.2, ЕСЛИ ЕСТЬ]

### Рабочая директория:
[ВСТАВЬТЕ ПУТЬ ИЗ ЧАСТИ 2.1]

### Состояние проекта:
[ВСТАВЬТЕ ВЫБРАННЫЙ ВАРИАНТ ИЗ ЧАСТИ 2.2]

### Режим выполнения:
[ВСТАВЬТЕ ВЫБРАННЫЙ РЕЖИМ ИЗ ЧАСТИ 3.1]

### Требуемое качество:
[ВСТАВЬТЕ ЗНАЧЕНИЕ ИЗ ЧАСТИ 3.2]

---

## ИНСТРУКЦИЯ

Выполни роль Pipeline Orchestrator согласно инструкциям в файле:
~/.claude/agents/pipeline-orchestrator.md

Запусти пайплайн с Phase 0 (Intent Intake) и выполняй все фазы последовательно.

Помни:
- Используй ТОЛЬКО явные вызовы Task tool для запуска агентов
- НЕ симулируй выполнение агентов
- Запрашивай подтверждение на каждом этапе (если выбран полуавтоматический режим)
- Соблюдай quality gates (минимум 7/10)
- Отвечай на русском языке

НАЧНИ ПАЙПЛАЙН СЕЙЧАС.
```

## Часть 5. Структура создаваемых артефактов

После запуска пайплайна будут созданы следующие файлы:

### Фаза инициализации:
- `PROJECT_PROFILE.md` - технический профиль проекта (внутренний)
- `PROJECT_PROFILE_HUMAN.md` - профиль для человека
- `PIPELINE_PROMPT.md` - мастер-промпт пайплайна

### Стадия 1 (Research & Analysis):
- `RESEARCH_REPORT.md` - результаты исследования
- `REQUIREMENTS.md` - системные требования
- `SCOPE_DEFINITION.md` - границы проекта

### Стадия 2 (Architecture):
- `ARCHITECTURE_OVERVIEW.md` - обзор архитектуры
- `FEATURES_INDEX.md` - индекс фич
- `ROADMAP_*.md` - TDD roadmaps для каждой фичи

### Стадия 3 (Development) - для каждой фичи:
- `IMPLEMENTATION_REPORT_*.md` - отчёт об имплементации
- `TEST_REPORT_*.md` - отчёт о тестах
- `CODE_REVIEW_REPORT_*.md` - отчёт code review
- `FEATURE_VERIFICATION_*.md` - верификация фичи с оценкой качества

### Финальная стадия:
- `SYSTEM_VERIFICATION_REPORT.md` - финальная верификация системы
- `DOCUMENTATION_*.md` - документация проекта
- `RELEASE_PACKAGE_*.md` - пакет для релиза

## Дополнительная информация

### Что делает оркестратор:

1. **Принимает** ваш человеческий замысел
2. **Генерирует** профиль проекта через Project Profile Generator
3. **Создаёт** мастер-промпт пайплайна через Pipeline Prompt Generator
4. **Запускает** агентов исследования (Research, System Analyst)
5. **Запускает** агентов архитектуры (Solution Architect, Feature Decomposer)
6. **Запускает** TDD Planner для создания roadmaps
7. **Запускает** цикл разработки для каждой фичи (Developer → Test → Review → Verify)
8. **Выполняет** финальную верификацию и документацию

### Правила выполнения:

- Все агенты запускаются ТОЛЬКО через Task tool
- Каждая фаза требует явного подтверждения человека
- Quality gate: минимум 7/10 для продолжения
- При несоответствии качества - перезапуск этапа

### Стоп-команды:

В любой момент вы можете остановить пайплайн и внести коррективы.
