# QUALITY_SCORING.md

## Назначение документа

QUALITY_SCORING.md определяет **единую систему оценки качества результатов работы агентов**
в мультиагентском пайплайне разработки.

Документ отвечает на вопросы:

- как оценивается качество фич и стадий
- кто выставляет оценку
- какие критерии применяются
- что происходит при низкой оценке
- когда пайплайн может продолжаться

Документ является **обязательным контрактом** для всех verifier- и reviewer-агентов.

---

## Общая модель оценки

### Шкала качества

Качество оценивается по шкале **от 0 до 10**:

| Score | Интерпретация                             |
|-------|-------------------------------------------|
| 0–3   | Неприемлемо                               |
| 4–6   | Ниже допустимого                          |
| 7–8   | Приемлемо, но требует доработок           |
| 9     | Высокое качество (минимум для acceptance) |
| 10    | Отлично / эталонно                        |

---

### Минимальные пороги

- **Минимально допустимый score:** `9`
- **Score < 9:** обязательный возврат в цикл исправлений
- **Score ≥ 9:** фича / стадия считается принятой

Никакие исключения не допускаются.

---

## Уровни оценки качества

Оценка применяется на **трёх уровнях**:

1. Feature-level (отдельная фича)
2. Stage-level (этап пайплайна)
3. System-level (проект в целом)

---

## 1. Feature-Level Scoring

### Кто оценивает

- Feature Verifier Agent (основной)
- Code Reviewer Agent (вклад)
- Test Engineer Agent (вклад)

Итоговый score выставляет **Feature Verifier Agent**.

---

### Критерии оценки (Feature-Level)

| Критерий                    | Описание                          |
|-----------------------------|-----------------------------------|
| Scope Compliance            | Реализована ровно заявленная фича |
| TDD Compliance              | Все тесты из ROADMAP выполнены    |
| Architectural Compliance    | Соблюдена архитектура             |
| Profile Compliance          | Соблюден AGENT_PROFILE            |
| Code Quality                | Читаемость, структура, чистота    |
| Test Coverage               | Полнота и уместность тестов       |
| Error Handling              | Корректная обработка ошибок       |
| Non-Functional Requirements | Производительность, стабильность  |
| Documentation               | Корректный IMPLEMENTATION_REPORT  |

---

### Пример расчёта score

Каждый критерий оценивается от 0 до 10.  
Итоговый score = **минимум** по всем критериям.

📌 **Важно:**
> *Один проваленный критерий → вся фича не принята.*

---

### Интерпретация Feature Score

| Score | Действие                                  |
|-------|-------------------------------------------|
| < 7   | Немедленный возврат в разработку          |
| 7–8   | Возврат в разработку с указанием дефектов |
| ≥ 9   | Фича принята                              |

---

## 2. Stage-Level Scoring

### Что оценивается

- полнота выполнения стадии
- согласованность артефактов
- отсутствие противоречий
- готовность к следующему этапу

### Кто оценивает

- Pipeline Orchestrator
- Stage Verifier Agent (если применимо)

---

### Критерии оценки (Stage-Level)

| Критерий              | Описание                                |
|-----------------------|-----------------------------------------|
| Artifact Completeness | Все обязательные артефакты присутствуют |
| Internal Consistency  | Нет логических противоречий             |
| Coverage              | Все требования / фичи покрыты           |
| Traceability          | Прослеживаемость между артефактами      |
| Readiness             | Готовность к следующей стадии           |

---

### Правила Stage Acceptance

- **Score ≥ 9:** стадия закрывается
- **Score < 9:** стадия повторяется

Частичное закрытие стадии запрещено.

---

## 3. System-Level Scoring

### Когда применяется

После завершения всех фич и стадий.

### Кто оценивает

- System Verifier Agent
- Pipeline Orchestrator

---

### Критерии оценки (System-Level)

| Критерий                   | Описание                |
|----------------------------|-------------------------|
| Feature Completion         | Все фичи приняты        |
| Integration Consistency    | Корректная интеграция   |
| Architecture Integrity     | Архитектура соблюдена   |
| NFR Fulfillment            | НФ требования выполнены |
| Documentation Completeness | Документация полная     |
| Deployment Readiness       | Готовность к деплою     |

---

### System Acceptance Rules

- **Score ≥ 9:** проект считается завершённым
- **Score < 9:** возврат к проблемной стадии

---

## Правила возврата и исправлений

### Цикл исправлений (MANDATORY)

```text
Develop → Test → Review → Verify
           ↑               ↓
           └── Fix Request ┘
````

* Количество циклов не ограничено
* Ограничений по “попыткам” нет
* Каждый цикл обязан улучшать score

---

## Запреты и ограничения

* Запрещено “усреднять” оценки
* Запрещено принимать фичу при score < 9
* Запрещено закрывать стадию частично
* Запрещено игнорировать нарушения профиля

---

## Human-in-the-Loop влияние

Человек:

* **не выставляет score**
* может:

    * остановить пайплайн
    * запросить пересмотр
    * отклонить результат вне зависимости от score

📌 Score — технический критерий, human approval — управленческий.

---

## Канонический принцип (зафиксировать)

> **Качество обеспечивается не доверием к агентам,
> а формальными критериями и циклической верификацией.**
