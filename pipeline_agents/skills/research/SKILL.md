# Research Skill

## Назначение

Проводит полное, всестороннее исследование по заданной теме с итеративной оценкой качества и привлечением пользователя для уточнения деталей.

## Когда использовать

Используйте этот навык когда пользователь запрашивает:
- Изучение новой технологии или фреймворка
- Анализ архитектурных подходов
- Исследование лучших практик (best practices)
- Сравнительный анализ инструментов или решений
- Изучение предметной области (domain research)
- Анализ существующих решений в кодовой базе

## Процесс исследования

### Фаза 1: Инициализация

**1.1 Определение цели исследования**

Попросите пользователя уточнить:
- Конкретную тему исследования
- Цель исследования (что нужно узнать/решить)
- Контекст применения (зачем эта информация нужна)
- Уровень глубины (обзор vs детальный анализ)

**1.2 Оценка полноты запроса**

Оцените исходный запрос по шкале 0-1:
- `1.0` - запрос максимально конкретен, цель ясна, контекст очевиден
- `0.7-0.9` - запрос понятен, но требует некоторых уточнений
- `0.4-0.6` - тема ясна, но цель и контекст размыты
- `0.0-0.3` - требуется существенное уточнение

Если оценка **<= 0.9**: задайте уточняющие вопросы через `AskUserQuestion`.

### Фаза 2: Сбор информации

**2.1 Первичный сбор**

Используйте следующие методы (выбирайте подходящие):

- **WebSearch** - для поиска актуальной информации, документации, статей
- **mcp__web_reader__webReader** - для глубокого изучения конкретных ресурсов
- **Grep** - для поиска в кодовой базе (если применимо)
- **Read** - для изучения конкретных файлов
- **Glob** - для поиска паттернов файлов

**2.2 Стратегия поиска**

Начните с:
1. Официальной документации (если есть)
2. Академических или технических статей
3. Лучших практик и стандартов индустрии
4. Примеров использования
5. Сравнительных материалов

**2.3 Оценка качества сбора**

После первичного сбора оцените:
- Полнота охвата темы (0-1)
- Актуальность источников (0-1)
- Разнообразие перспектив (0-1)

Общая оценка = среднее по трём метрикам.

Если **<= 0.9**: задайте вопросы для уточнения направлений исследования.

### Фаза 3: Структурирование

**3.1 Организация информации**

Структурируйте собранные данные по разделам:
- Обзор и ключевые понятия
- Технические детали
- Преимущества и недостатки
- Сравнение с альтернативами
- Примеры применения
- Рекомендации

**3.2 Оценка структуры**

Оцените:
- Полноту охвата аспектов темы (0-1)
- Логичность организации (0-1)

Если **<= 0.9**: уточните у пользователя, какие аспекты требуют углубления.

### Фаза 4: Углубление

**4.1 Детализация слабых мест**

На основе предыдущих оценок:
- Углубитесь в недостаточно освещённые аспекты
- Проведите дополнительный поиск по узким темам
- Найдите кейсы и примеры

**4.2 Оценка глубины**

Оцените:
- Детальность каждого раздела (0-1)
- Наличие конкретных примеров (0-1)

Если **<= 0.9**: проведите дополнительное исследование.

### Фаза 5: Синтез

**5.1 Формирование выводов**

Сформулируйте:
- Ключевые выводы по теме
- Рекомендации с учётом контекста пользователя
- Рекомендации по дальнейшему изучению

**5.2 Финальная оценка**

Оцените итоговое исследование:
- Полнота охвата темы (0-1)
- Глубина проработки (0-1)
- Практическая применимость (0-1)
- Качество источников (0-1)

Общая оценка = среднее. Если **<= 0.9**, получите фидбек у пользователя.

### Фаза 5.5: Разрешение открытых вопросов (ОБЯЗАТЕЛЬНАЯ)

**5.5.1 Выявление открытых вопросов**

После синтеза проанализируйте исследование на наличие:
- Вопросов, требующих вводных от пользователя
- Аспектов, которые не были полностью покрыты
- Технических деталей, зависящих от проектных решений

**5.5.2 Обработка открытых вопросов**

Если выявлены открытые вопросы:

1. **Классифицируйте каждый вопрос:**
   - Требующий ответа пользователя (блокирует завершение)
   - Требующий дополнительного исследования (можно изучить самостоятельно)
   - Рекомендательный (можно оставить как есть)

2. **Для вопросов, требующих ответа пользователя:**
   - Используйте `AskUserQuestion` для получения ответов
   - НЕ создавайте финальный отчёт, пока не получите ответы
   - После получения ответов проведите дополнительное исследование

3. **После получения ответов:**
   - Обновите исследование с учётом новых данных
   - Добавьте полученную информацию в соответствующие разделы
   - Удалите разрешённые вопросы из списка открытых

4. **Для вопросов, не блокирующих завершение:**
   - Оставьте в отчёте как "Рекомендации по дальнейшему изучению"
   - Или перенесите в отдельный раздел "Будущие исследования"

**5.5.3 Критерий завершённости**

Исследование считается полным только когда:
- Нет вопросов, блокирующих практическое применение результатов
- Все вопросы, требующие ответа пользователя, разрешены
- Оставшиеся вопросы только рекомендательные

### Фаза 6: Документирование

**6.1 Создание отчёта**

Создайте markdown-файл со следующей структурой:

```markdown
# Исследование: [Тема]

## Метаданные
- **Дата**: [дата]
- **Контекст**: [контекст исследования]
- **Итоговая оценка качества**: [0-1]

## 1. Введение
[Краткий обзор темы и цели исследования]

## 2. Основные понятия
[Ключевые определения и концепции]

## 3. Детальный анализ
### 3.1 [Подраздел]
[Детальное описание...]

## 4. Сравнительный анализ
[Сравнение альтернатив, если применимо]

## 5. Практические рекомендации
[Рекомендации с учётом контекста]

## 6. Источники
- [Источник 1](URL)
- [Источник 2](URL)
...

## 7. Будущие исследования (опционально)
[Аспекты для изучения в будущем, не блокирующие текущие результаты]

---

**Создано**: Research Skill
**Оценка этапов**:
- Инициализация: [0-1]
- Сбор информации: [0-1]
- Структурирование: [0-1]
- Углубление: [0-1]
- Синтез: [0-1]
```

**6.2 Именование файла**

Используйте формат: `research_-[тема]_[YYYY-MM-DD].md`

## Правила

1. **Итеративность** - постоянно оценивайте качество и уточняйте направление
2. **Вовлечение пользователя** - если оценка <= 0.9, обязательно задавайте вопросы
3. **Актуальность** - проверяйте дату источников, предпочитайте свежие материалы
4. **Критическое мышление** - анализируйте противоречия в источниках
5. **Практическая ориентация** - связывайте исследования с контекстом пользователя
6. **Честность** - если информации недостаточно, укажите это явно

## Критерии оценки

| Этап | Критерий | 1.0 | 0.5 | 0.0 |
|------|----------|-----|-----|-----|
| Инициализация | Понимание цели | Чётко сформулирована | Общее представление | Неясно |
| Сбор | Полнота источников | Все ключевые источники | Основные источники | Фрагментарно |
| Сбор | Актуальность | < 2 лет | 2-5 лет | > 5 лет |
| Структура | Логика | Идеальная организация | Есть пробелы | Хаотично |
| Углубление | Детальность | Все аспекты подробно | Ключевое подробно | Поверхностно |
| Синтез | Практичность | Конкретные рекомендации | Общие рекомендации | Без рекомендаций |
