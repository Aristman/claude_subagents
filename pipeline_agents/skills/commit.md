# Git Commit Skill

## Назначение

Создает git commit с осмысленным сообщением для логического блока изменений, выполненных в ходе работы агента.

## Когда использовать

Этот навык должен использоваться автоматически:
- После завершения этапа проектирования (архитектура, требования, декомпозиция)
- После завершения реализации фичи
- После significant изменений в документации

## Процесс создания коммита

### Шаг 1: Анализ изменений

Выполните:
```bash
git status
```

Если есть untracked файлы или изменения - продолжайте.

### Шаг 2: Просмотр изменений

Выполните:
```bash
git diff
```

Для staged изменений:
```bash
git diff --staged
```

### Шаг 3: Формирование commit message

Используйте следующий формат:

```
<тип>: <краткое описание>

<расширенное описание при необходимости>
```

**Типы изменений:**
- `feat` - новая функциональность
- `fix` - исправление бага
- `docs` - изменения в документации
- `arch` - архитектурные изменения
- `refactor` - рефакторинг
- `test` - добавление тестов
- `chore` - прочие изменения
- `ci` - изменения в CI/CD

### Шаг 4: Добавление файлов

Добавьте только файлы, относящиеся к текущему логическому блоку:
```bash
git add <файлы>
```

**НЕ добавляйте:**
- `.env` файлы с секретами
- временные файлы
- файлы сensitive данными
- файлы, не относящиеся к текущему блоку

### Шаг 5: Создание коммита

Используйте HEREDOC для многострочного сообщения:

```bash
git commit -m "$(cat <<'EOF'
<commit message>
EOF
)"
```

### Шаг 6: Проверка

Проверьте результат:
```bash
git log -1 --stat
```

### Шаг 7: Push (опционально)

Не делайте push автоматически, если это не требуется явно.

## Правила

1. **Атомарность** - один коммит = одна логическая единица работы
2. **Ясность** - сообщение должно быть понятным будущему разработчику
3. **Консистентность** - следуйте формату конвенциональных коммитов
4. **Качество** - не коммитьте незавершенную работу или сломанный код
5. **Безопасность** - никогда не коммитьте секреты

## Примеры

```
feat: добавить JWT аутентификацию в REST API

Реализована JWT-based аутентификация с refresh tokens.
Добавлены эндпоинты /login, /refresh, /logout.
```

```
arch: спроектировать layered architecture для backend сервиса

Определены слои: transport, business logic, data access.
Спроектированы DTO и мапперы между слоями.
```

```
docs: добавить README с инструкциями по установке

Добавлен README.ru.md и README.en.md с описанием проекта,
требованиями и инструкциями по развертыванию.
```
