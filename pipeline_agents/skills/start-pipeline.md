# Start Pipeline Skill

## Назначение

Запускает полный цикл мультиагентной разработки программного обеспечения через pipeline-orchestrator.

## Когда использовать

Используйте этот навык когда пользователь хочет:
- Создать новый продукт с нуля
- Пройти полный цикл разработки от идеи до релиза
- Запустить TDD-ориентированную разработку с агентами

## Как работает

Этот навык запускает **pipeline-orchestrator** агент, который:
1. Принимает человеческий intent
2. Запускает project-profile-generator для создания профиля проекта
3. Запрашивает подтверждение профиля у пользователя
4. Запускает pipeline-prompt-generator для создания master prompt
5. Запускает все downstream агенты в правильном порядке:
   - research-agent
   - system-analyst
   - solution-architect
   - feature-decomposer (с автоматическим созданием TDD roadmaps)
   - developer-agent (для каждой фичи)
   - test-engineer
   - code-reviewer
   - feature-verifier
   - system-verifier
   - documentation-agent
   - release-devops

## Использование

Когда пользователь запускает `/start-pipeline` или дает команду "начни пайплайн":

1. **Соберите весь контекст от пользователя:**
   - Цель проекта
   - Краткое описание
   - Платформы
   - Ожидания (качество, TDD, архитектура)
   - Ограничения

2. **Сформируйте промпт для pipeline-orchestrator:**

   ```
   Запусти пайплайн разработки со следующими параметрами:

   ---
   Human Intent:
   {собранный контекст от пользователя}
   ---

   Выполни весь процесс workflow согласно твоим инструкциям.
   Не пропускай этапы.
   Запрашивай одобрение пользователя на контрольных точках.
   ```

3. **Запустите Task tool:**
   ```
   subagent_type: pipeline-orchestrator
   prompt: {сформированный промпт}
   ```

## Контрольные точки одобрения

Пайплайн будет автоматически запрашивать одобрение на следующих этапах:

1. **После создания профиля проекта** (PROJECT_PROFILE_HUMAN.md)
   - Пользователь видит, как система поняла задачу
   - Может запросить изменения или продолжить

2. **После создания master prompt** (PIPELINE_PROMPT.md)
   - Пользователь видит полный план разработки
   - Финальное подтверждение перед началом реализации

3. **На каждом quality gate** (если требуется)
   - После завершения каждой стадии
   - При отклонении качества

## Выходные артефакты

После успешного выполнения пайплайна будут созданы:

### Документация:
- PROJECT_PROFILE.md
- PROJECT_PROFILE_HUMAN.md
- PIPELINE_PROMPT.md
- ANALYSIS.md
- TECH_REQUIREMENTS.md
- SCOPE.md
- ARCHITECTURE_OVERVIEW.md
- WORK_BREAKDOWN.md
- FEATURES_INDEX.md
- ROADMAP_*.md (для каждой фичи)

### Реализация:
- Исходный код (backend, mobile, web)
- Тесты (unit, integration, e2e)
- IMPLEMENTATION_REPORT_*.md

### Верификация:
- FEATURE_VERIFICATION_REPORT_*.md
- SYSTEM_VERIFICATION_REPORT.md

### Документация:
- README.ru.md, README.en.md
- INSTALLATION.ru.md, INSTALLATION.en.md
- DEPLOYMENT.ru.md, DEPLOYMENT.en.md
- CONFIGURATION.ru.md, CONFIGURATION.en.md

## Пример запуска

```
Пользователь: Я хочу создать мобильное приложение для управления задачами
            с backend-сервисом, авторизацией и синхронизацией.

Запуск /start-pipeline:

1. Собрать контекст:
   - Цель: Мобильное приложение для управления личными задачами
   - Платформы: Backend, Mobile (Android/iOS)
   - Ожидания: Качество 9/10, TDD, расширяемая архитектура
   - Ограничения: Современные технологии, без vendor lock-in

2. Запустить pipeline-orchestrator с собранным контекстом

3. Оркестратор автоматически:
   - Создаст профиль проекта
   - Запросит одобрение
   - Создаст master prompt
   - Запросит финальное одобрение
   - Запустит весь пайплайн
```

## Важно

- **НЕ пропускайте этапы** — пайплайн должен выполняться полностью
- **Запрашивайте одобрение** — пользователь должен контролировать процесс
- **Следите за качеством** — каждый агент должен проходить верификацию
- **Коммитьте результаты** — каждый этап должен быть зафиксирован в git

## Проблемы и их решение

| Проблема | Решение |
|----------|---------|
| Оркестратор не запускается | Используйте Task tool с subagent_type="pipeline-orchestrator" |
| Профиль не показывается | Проверьте наличие AskUserQuestion в tools оркестратора |
| TDD roadmaps не создаются | Проверьте Phase 6 в feature-decomposer.md |
| Профили не находятся | Проверьте Profile Resolution Process в developer-agent.md |
| Коммиты не создаются | Проверьте наличие /commit skill и Bash tool |
| WebSearch не работает | Проверьте наличие WebSearch в tools research-agent |
| Bash команды не работают | Проверьте settings.local.json проекта |
